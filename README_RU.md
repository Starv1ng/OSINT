# OSINT Intelligence Platform

## Описание

Распределенная OSINT (Open Source Intelligence) платформа с микросервисной архитектурой для автоматизированного сбора и анализа информации из открытых источников.

## Архитектура

Система состоит из следующих компонентов:

- **API Service** (FastAPI) - REST-шлюз и веб-интерфейс
- **Worker Service** (Celery) - Асинхронное выполнение задач
- **PostgreSQL** - Хранение заданий и статусов
- **Redis** - Брокер сообщений для очереди задач
- **Elasticsearch** - Индексация и поиск результатов
- **MinIO** - Хранение файлов и артефактов
- **Neo4j** - Граф связей и сущностей
- **Kibana** - Визуализация данных (опционально)

## Функциональность

### Анализ входных данных
- Автоматическое определение типа входных данных (email, username, домен, имя, телефон, URL, IP, хэш)
- Оценка уверенности классификации (0.0-1.0)
- Извлечение вторичных индикаторов из входных данных

### OSINT-модули

**Многоцелевые сборщики (MPG):**
- Search Engine - запросы Google/DuckDuckGo
- Web Spider - извлечение HTML-контента

**Экстракторы метаданных (MEI):**
- Извлечение email из сырого контента
- Извлечение телефонных номеров
- Извлечение username
- Извлечение URL изображений

**Социальные сети:**
- Поиск профилей Twitter/X
- Поиск профилей LinkedIn
- Поиск пользователей/репозиториев GitHub

**Инфраструктура:**
- DNS/WHOIS запросы
- Анализ доменов

**Безопасность:**
- Поиск утечек данных
- Верификация email

### Конвейер обработки

1. **Анализ входных данных** - Автоматическое определение типа и маршрутизация модулей
2. **Выполнение модулей** - Параллельное выполнение выбранных модулей
3. **Фильтрация результатов** - Удаление шума (HTML-атрибуты, спам, общие домены)
4. **Оценка** - Автоматическая оценка релевантности (0.0-1.0)
5. **Дедупликация** - Удаление дубликатов
6. **Индексация** - Сохранение в Elasticsearch для быстрого доступа

### Режимы поиска

**Статический режим:**
- Предопределенные наборы модулей для каждого типа данных
- Однократное выполнение
- Быстрый и предсказуемый

**Динамический режим:**
- Итеративное выполнение (до 5 итераций)
- Автоматическое извлечение индикаторов из результатов
- Прогрессивное обнаружение связанной информации
- Настраиваемые пороги релевантности

## Установка

### Требования
- Docker 20.10+
- Docker Compose 2.0+
- Минимум 8GB RAM
- 20GB свободного места на диске

### Быстрый старт

```bash
# Клонировать репозиторий
git clone https://github.com/Starv1ng/OSINT.git
cd OSINT

# Запустить все сервисы
docker-compose up -d

# Просмотр логов
docker-compose logs -f api worker

# Доступ к веб-интерфейсу
# http://localhost:8000
```

### Конфигурация

Файлы окружения в директории `envs/`:

- `api.env` - Конфигурация API-сервиса
- `worker.env` - Конфигурация Worker-сервиса
- `worker_dynamic.env` - Конфигурация динамического поиска (опционально)

Ключевые настройки:
- `DATABASE_URL` - Подключение PostgreSQL
- `CELERY_BROKER` - Подключение Redis
- `ELASTICSEARCH_URL` - Endpoint Elasticsearch
- `MAX_ITERATIONS` - Максимальное количество итераций (динамический режим)
- `MODULE_TIMEOUT_SECONDS` - Таймаут на модуль

## Использование

### Веб-интерфейс

1. Перейти на `http://localhost:8000`
2. Ввести поисковый запрос (email, имя, username и т.д.)
3. Система автоматически определит тип входных данных
4. Просмотр результатов в реальном времени по мере завершения модулей
5. Доступ к истории заданий по адресу `/jobs`
6. Проверка статуса системы по адресу `/system`

### API endpoints

**Создать поиск:**
```bash
POST /api/v1/ingest/name
Content-Type: application/json

{
  "value": "поисковый-запрос",
  "execution_mode": "normal"
}
```

**Получить статус задания:**
```bash
GET /api/v1/jobs/{job_id}
```

**Список заданий:**
```bash
GET /api/v1/jobs?limit=20&offset=0
```

**Статус системы:**
```bash
GET /api/v1/health
```

## Разработка

### Структура проекта

```
services/
├── api/                    # FastAPI сервис
│   ├── app/
│   │   ├── api/           # Обработчики маршрутов
│   │   ├── templates/     # Jinja2 шаблоны
│   │   ├── static/        # CSS, JS файлы
│   │   └── tasks/         # Celery клиент
│   └── requirements.txt
├── worker/                 # Celery worker
│   ├── tasks/
│   │   ├── modules/       # OSINT модули
│   │   │   ├── base/      # Базовые классы
│   │   │   ├── mei/       # Экстракторы метаданных
│   │   │   ├── social_media/
│   │   │   ├── infrastructure/
│   │   │   ├── security/
│   │   │   └── utils/     # Анализ входных данных, фильтрация
│   │   ├── coordinator.py # Координация задач
│   │   └── orchestrator.py
│   └── config/            # Конфигурация динамического поиска
└── infra/                 # Инициализация БД
```

### Добавление новых модулей

1. Создать класс, наследующий `BaseSearcher`
2. Реализовать `search()`, `get_supported_types()`, `get_priority()`
3. Зарегистрировать в оркестраторе
4. Добавить в `INDICATOR_MODULE_MAPPING` при необходимости

### Запуск тестов

```bash
# Проверка окружения
python verify_env.py

# Тесты в контейнере worker
docker-compose exec worker python test_dynamic_search.py
```

### Пересборка сервисов

```bash
# Пересобрать конкретный сервис
docker-compose up -d --build api

# Пересобрать все сервисы
docker-compose up -d --build
```

## Текущие ограничения

- Не настроены реальные API-ключи (модули возвращают mock-данные)
- Аутентификация отключена в режиме разработки
- Ограниченная реализация rate limiting
- Отсутствует слой кэширования для повторных запросов
- Базовая обработка ошибок в некоторых модулях
